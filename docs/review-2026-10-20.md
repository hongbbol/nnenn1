## 2. 잘못 가고 있는 것 — 우선순위순

### 🔴 A. 데이터는 있는데 앱에 안 흐른다 (가장 큰 레버, 수정은 ETL 한 곳)

| 항목 | nnenn2에 있나 | 시드에 있나 | 결과 |
|---|---|---|---|
| 무기 인산염(인산·phosphate) | 458 SKU | 0 | CKD 하드 게이트 작동 0건 |
| DL-메티오닌·염화암모늄(산성화제) | 400+ SKU | 0 | 옥살레이트 금기 필터 0건 |
| 비타민C·크랜베리 | 133 / 430 SKU | 0 | 옥살레이트 금기 필터 0건 |
| 첨가당(sugar·dextrose·caramel) | 166+ SKU | 0 | 당뇨 배제 0건 |
| 양파·마늘(allium) | 4 SKU | 0 | 공통 독성 필터 0건 |
| 마그네슘 | 458 영양행 | 컬럼 없음 | 스트루바이트 Mg 레버 불가 |
| 칼슘(Ca:P) | 1,239 영양행 | 컬럼 없음 | CKD Ca:P 규칙 불가 |

원인: `build_foods_json.py`의 `INGREDIENT_SYNONYMS`가 단백질·곡물 7종만 정규화한다. 엔진(`rules.ts KEYWORDS`)은 레지스트리 부록 A대로 첨가물 토큰을 기다리고 있고, 테스트는 토큰을 수동으로 넣은 예시 데이터로만 통과한다. **엔진의 안전 필터 5종이 실데이터에서는 전부 무효다.**

### 🔴 B. 추천 엔진이 기획·레지스트리와 어긋남 (실데이터 42 시나리오 실행 결과)

1. **건식/습식 선호가 반영 안 됨** — `dietPref`를 받기만 하고 안 씀. 42개 중 20개에서 반대 제형 추천.
2. **감량 목표 = 항상 습식 파우치** — kcal/100g 비교라 수분 80% 습식이 유리. 스키마 §3-2가 정한 per-1000kcal/DM 기준 위반.
3. **췌장염 = IBD와 동일 결과** — 레버 없음. 게다가 ETL `CONDITION_RULES`는 'low fat/저지방'→췌장염, 온보딩 설명은 "췌장염: 저지방 필요"인데 **레지스트리 §3-H는 "고양이는 지방 제한 근거 없음, 가수분해 단백+칼로리 확보가 1차"**라고 정반대로 적고 있다. 문서·ETL·UI 세 곳이 서로 모순.
4. **동반 질환 무시** — 우선 질환만 채점(신부전+당뇨 → 탄수 안 봄). 레지스트리 §4-4 "하위 질환 soft 반영"·"우선 질환 입력 질문" 미구현.
5. **다양성 규칙 미구현** — dev-plan §4.5(2위는 다른 제형 우선) 없음. 인스팅트 오리 1종이 16/42 시나리오 TOP2, 같은 브랜드 형제 제품 쌍 빈발.
6. **"데이터 부족 시 보류" 미구현** — 레지스트리 §3-0·스키마 §5-3은 CKD·당뇨에서 핵심 레버 결측이면 상위 노출 금지. 현재는 0.3점+경고로 순위에 남김. kr 주식 960 중 **인 결측 361(38%)**, kcal 결측 221, 당뇨 탄수 계산 가능 445(46%).
7. **옥살레이트 모드는 사실상 빈 모드** — kr 옥살레이트 처방식 태그 0, 산성화제 필터 0건 → 2위가 일반 뷰티 파우치.
8. 랜딩 예시(로얄캐닌·힐스)와 같은 조건의 실제 결과(이퀼리브리오·파미나)가 다름 — 예시가 하드코딩.

### 🟠 E. 구조적 문제

- **문서가 현실을 못 따라감**: README "M1까지 완료·테스트 56개", 이슈 #16 6월 상태, nnenn2 CLAUDE.md 상단 "현재 상태 2026-06-11", PENDING.md 1,540줄(이력 블록 혼재). 새 세션 cold-start 비용이 큼.
- **레지스트리 (b) 점수식이 미작성인 채 엔진이 구현됨** — 레지스트리 §6 "다음 작업: desirability 점수식·가중치"가 그대로 남아 있고, `scorer.ts`의 가중치(0.55/0.15/…)는 문서 근거 없이 에이전트가 정한 값. 수의사 검수 0회.
- **비교 기능이 as-fed % 직접 비교** — 습식 단백 8% vs 건식 32%를 나란히 놓음(스키마 §4 예시 A가 경고한 바로 그 오류). 월 비용·전환 가이드는 미구현(가격 0건).
- **추천 스냅샷 고정** — `recommendations.result`에 전체 결과 저장. 10/10 힐스 세대 교체(S1456·S2052) 같은 수정이 기존 사용자 결과엔 영향 없음. 재추천 버튼 없음.
- **처방식 분류가 이름 휴리스틱** — 빌드 경고 "처방식인데 condition_fit 매핑 실패" 39건(알러지 처방식은 대응 옵션 자체가 없음), 'hepatic'→췌장염, '결석'→스트루바이트 오매핑(Trovet RID 사례). kr 처방식 라인 18개는 수동 큐레이션이 현실적.
- **병렬 작업 사고 이력**: 10/02 SKU ID 충돌(워크트리별 잠금 불가시), 10/06 nnenn2 main이 nnenn1보다 뒤처짐. 현재 워크트리 6개는 전부 clean·main 뒤 → 삭제 가능. nnenn1 미머지 브랜치 중 `fix/legacy-avoid-ingredients`(6/8, 테스트 1개)·`data/user-confirm-p1-hills`(10/20 3커밋, main에 포함 여부 확인 필요)만 실질.
- **국산 사료 공백**: 설계상 한국 본사 브랜드 제외(하림·대주만 편입). 한국 사용자가 '현재 사료'를 못 찾는 경우가 많을 것. `BRAND_EXCLUSIONS.md` §2 약 100개.
- 판매처 안내([3] `kr_seller_count 1 AND kr_single_seller Yes`, 18건)는 시트에만 있고 시드·앱에 미배선.

## 3. 기획 대비 어긋남 (dev-plan §1.3 MVP 범위)

방향성 판단 두 가지:
- 레지스트리 §3-0은 **"데이터 좋은 모드(요로·비만)부터 출시, CKD·당뇨는 데이터 성숙 후"**라고 썼는데, 랜딩 히어로와 포지셔닝은 신부전 중심. 자기 문서와 반대.
- 비목표 "망라가 아닌 신뢰 우선"은 데이터 트랙에서 "망라"로 기울었다. 틀린 건 아니지만, 그 사이 서비스 트랙이 4개월 멈췄다. **목표가 '사료 DB'인지 '서비스'인지** AUTONOMY_POLICY §1은 서비스라고 적어 놓고 Q1~Q6 답이 없어 실행이 안 된다.
